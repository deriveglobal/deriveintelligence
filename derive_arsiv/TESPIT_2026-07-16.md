## 5. GAPS & DRIFT (honest findings)

1. **Ledger is 100% drafted, 0% human-approved.** `onayli = 0` for every type (functions, endpoints, crons, tables); 213 `taslak`. The "trust" leg of the moat — human confirmation of what each capability *does* — has not been done. Not blocking, but it's the difference between "AI thinks it knows the house" and "the house is confirmed."
2. **2 undefined + 1 changed in the ledger:** `ogren_sor` and `ogren_bilinen` are `tanimsiz`; `bi_icgoru` is `degisti` (its columns changed when narration was added — fingerprint flagged it for re-approval). The guard is working; these just need a definition pass.
3. **`bi_ogrenme` does not exist.** The docs propose it as the learning-knowledge store; the live system implements learning through `bi_sistem_sorusu` + the trigger instead. It works (proven), but it diverges from the documented schema, and the two `ogren_*` functions aren't registered in the ledger.
4. **Some insights are empty.** The 4 `marka-trend` insights (2026-07-15) have blank `anlati` — v1 leftovers from before LLM narration. Cosmetic, but the cockpit would surface them.
5. **DB bloat:** 23 `_yedek` / `_olu` tables = **766 MB** reclaimable (biggest: `bi_stok_hareketleri_olu_yedek` 296 MB, six `bi_satis_faturalari_yedek_*` copies ~452 MB). Disk is 59% full (21G/38G) — not urgent, but easy cleanup.

## 6. WHERE WE'RE GOING — the road to the cockpit

In order. The cockpit is deliberately last; everything before it is substance and trust.

1. **Complete the cost.** Fold the supplier rebate (`bi_tedarikci_tesvik`, 20 rows) into `maliyet(sku,ay)` → true net margins. First run the read-only sizing to see gross vs certain-net (fatura-altı) vs potential-net (max), then settle the one fork only you can answer: **is the ERP cost already net-of-invoice, or gross?**
2. **Unfreeze ERP ingest.** Diagnose #100/#101/#102 and get one fresh load flowing — or consciously ship cockpit v1 on a static snapshot. The market side proves the pipeline pattern already works.
3. **Close the trust leg.** Approve the ledger (taslak→onayli), define `ogren_sor`/`ogren_bilinen`, re-approve `bi_icgoru`, and answer the pending `zararina_hacim` law (10 seconds).
4. **Finish the learning loop.** Either create `bi_ogrenme` as the documented store or formally adopt `bi_sistem_sorusu` as it; register the functions.
5. **Complete the dimensions.** DSO/stock/segment/season/customer into the backbone so the cockpit can pivot.
6. **Housekeeping.** Drop the 766 MB of dead/backup tables; clear the empty `marka-trend` insights.
7. **Build the cockpit.** Plug into existing contracts (`/api/bi/icgoru`, `finans-marka-sebep`, `finans-seri`, …). Each indicator carries its reliability mark (● certain / ◐ approximate / ◌ assumption). It's a consumer of the engine — no numbers computed in the UI.

**Immediate next action:** run the read-only net-margin sizing so we can see the size of the cost correction and make the gross/net call together.
